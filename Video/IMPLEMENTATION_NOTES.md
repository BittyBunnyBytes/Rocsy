# H3 prompt refinement implementation notes

## Trainer pattern examined

`Trainer/tagger.py` labels its auto-tag and clip-scout work as Hermes, but runs those tasks through llama-swap's OpenAI-compatible `/v1/chat/completions` API. It reads model IDs from llama config, enqueues the job with bunny-lock, waits for a `/api/internal/queue/proceed/{job_id}` callback, heartbeats the granted token, frees ComfyUI's loaded models before llama inference, unloads llama-swap afterward, and releases the token. The Trainer also exposes a separate Hermes skill file and reads agent logs for its UI.

## H3 implementation

- `backend/enhancer.py` now builds one system task with the three supplied reference files and the Studio text box prompt as the user task. It sends the request to local llama-swap and keeps generation mode, duration, and attached reference labels in context.
- The Enhancement settings view chooses any llama model ID and controls temperature, thinking level, top P, top K, min P, repeat penalty, seed, plus an arbitrary JSON object of additional llama request settings. Model options come from `/v1/models`.
- The Enhance button submits a background job and polls it. A job can be cancelled through `POST /api/enhancement/jobs/{job_id}/cancel`. The job waits for the shared bunny-lock queue, frees ComfyUI models, calls llama-swap, unloads the llama model, and releases the token. A queued job never starts inference before its proceed callback.
- The standalone Hermes gateway process is not invoked. This follows the Trainer's in-app “Hermes” tagging implementation, which gives the model an agent task but uses llama-swap directly. It has no Hermes tool calls or persistent Hermes session.

## Operational notes

The H3 Docker service needs `LLAMA_API_KEY` in its compose environment. The three markdown files are copied into the H3 backend image. Existing stored enhancement settings are read only for overlapping fields, so former DeepSeek key and guide settings are not sent to llama. The old Qwen service remains available for its unrelated service controls.

The first live smoke request reached llama but ran beyond three minutes with its old thinking default; it was stopped and its queue entry cleared. The new Qwen request sets nonthinking mode by default.

The final live test completed with the Qwen model, returned a 485-character refined prompt, restored the saved 4,000-token setting, and left the shared queue empty.

The output token cap was removed from the UI and saved settings. Requests send `max_tokens: -1` and `n_predict: -1` to llama.cpp so generation continues to EOS; the model context limit still applies. The thinking selector sends `reasoning_effort`, with an additional `enable_thinking: false` template flag for Qwen when Off is chosen.

The Enhancement settings now have a right-side live terminal. It lists recent in-memory prompt sessions and shows each session's prompt, queue wait and grant, ComfyUI memory release, llama model call, refined reply, errors, model unload, and queue release. It polls the job API while that settings view is open. These events describe the H3 task runner; the separate Hermes gateway process is not invoked.

The Studio now has a collapsed Enhance card above the H3 prompt. Its optional additional request is sent separately from the H3 prompt and kept in browser local storage. A completed refinement updates the existing syntax-highlighted prompt editor and briefly brightens its highlight layer before returning to the same palette. Job polling uses no-store responses, and llama chat now streams progress so the button and session log show generation activity.

Completed, failed, and cancelled refinement sessions (including completed prompts) are saved in H3's app state and restored after a container restart. The most recent 20 are kept.

## Agentic clip plans (2026-10-04)

- The collapsed Enhance card now has an Agentic button. Its expanded guide textarea instructs either Enhance or Agentic alongside the main H3 prompt.
- `backend/agentic.py` defines `::VIDEO` / `::END` blocks. Headers carry consecutive `id`, `action=NEW|EXTEND`, `mode=text|reference|keyframe`, `duration=5..15`, `refs`, `exclude`, `first`, and `last`; `EXTEND` also carries `from=<earlier id>`, `mode=reference`, and `frame=previous`. Reference header values use the attached aliases (such as `image1`). The parser rejects invented, contradictory, or excluded references before queueing.
- Enhance asks the local llama Hermes task to return a plan for requests with multiple videos or more than 15 seconds. The plan appears in the H3 prompt editor. Plain Generate declines a plan; Agentic sends it through Hermes for review before queueing. Agentic can also turn a freeform prompt and guide into a plan.
- The Agentic endpoint stores its planner log in Enhancement jobs. Planning takes a bunny-lock GPU turn, releases it and unloads llama before rendering. Each clip uses the ordinary `/api/generate` path and bunny-lock queue. Independent NEW clips enqueue immediately; EXTEND waits for its source render, uploads the source video and its final frame as H3 Reference assets, then queues Reference mode. An Agentic job finishes after all clips complete; cancelling it stops further submissions but leaves already submitted renders alone.
- The editor flash now brightens and glows its syntax-highlighted text for 1.5 seconds, adds a visible editor pulse, then returns to the original syntax colors.

## Reference-mode continuation correction (2026-10-04)

- Agentic `EXTEND` now plans and renders in H3 Reference mode. It uploads the preceding generated video and its final frame to a private reference pool, binds `{{CONTINUATION_VIDEO}}` and `{{CONTINUATION_FRAME}}` in the Hermes-authored prompt to their actual H3 reference labels, and submits both with the chosen original references. `refs=inherit` carries the source clip's selected original references; `exclude=` removes named originals.
- The earlier keyframe-only test proved queue chaining but showed looped motion; those three hand-written test clips were not a Hermes-planned Agentic run. No further renders were submitted while correcting the workflow. Agentic now always runs Hermes planning before queueing, including when a plan is already in the editor.

- The H3 Agentic code changes planner instructions, plan validation, reference uploads, and queue orchestration. They do not alter Hermes or H3 model weights. The deployed correction was checked with a Reference-workflow dry run; no new videos were rendered for it.

## Agentic hardening + finishing (2026-10-05)

- Every Hermes GPU turn goes through `_hermes_turn` (bunny-lock enqueue retried 3x, 6 h wait with a named timeout, always unload + release) and every llama call through `_hermes_chat` (3 tries on HTTP/connection/cut-off stream). `_error_text` gives a reason for APIError/TimeoutError, which used to stringify to ''.
- Bounded loops: plan repair max 6 (fails naming the last parser error), plan review max `agentic_review_rounds`+1 passes (then continues with the plan that passed every format check). Any first-draft planner error now goes to repair instead of failing.
- Footage review is advisory: unusable JSON is retried 3x per clip with the rejection reason, then the clip is kept as rendered; frame-sampling/queue failures skip review instead of failing; revisions still unresolved after 2 rounds keep the latest renders (`run.unresolved_reviews`). Source-frame grounding failures fall back to the validated plan. Clip renders back off 15/30/45 s between retries; prepare (final-frame upload) is retried once.
- Sessions stuck "awaiting_approval" that can't be restored at startup are marked interrupted (they used to block Resume/Delete forever).

Each step's render gets one unchanged retry. Outputs join the session lane with agentic_phase postedit/stitch (not continuation sources).
